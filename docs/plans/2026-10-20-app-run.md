# Apps in a task — Implementation Plan (pathfinder-dev-base)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Light format: each task gives
> goal, files, interfaces, behaviours (tests to write first) and pitfalls; write the code against the real files.

**Goal:** a project's apps (`apps:` in `agentic.yaml`) run in a task container, controlled through the bridge, with
their ports in the image label `agentic.apps`.

**Spec:** `docs/specs/2026-10-20-app-run-design.md`. **Reference implementation** (the test version, in daily use):
the agentic-dev-base test version — `image/bin/agentic-app`, `tests/bats/agentic-app.bats`, the `apps` parts of
`schema/agentic.schema.json`, `image/lib/config-rules.jq`, `derive/render-dockerfile.sh` (label `agentic.apps`),
`bridge/src/api.ts` (`POST /app`) and `bridge/src/task.ts` (`app` events). Port behaviour from there; adapt to this
repo's code, which differs (sessions, no host app CLI, the bridge controls apps).

**Where:** this repository, branch `feat/app-run`. Run tests in WSL at the checkout (bats, jq, yq, shellcheck; `cd bridge && npm test`), every call
wrapped in `timeout`.

## Global Constraints

- This repo's CLAUDE.md: thin host CLI (no git, no build on the host), `set -euo pipefail`, shellcheck-clean, a bats
  test per behaviour written first; bridge: strict tsc, eslint, vitest first, no new dependency.
- No company resources; examples use `example.com`. No secret in a label, log, event or `agentic.yaml`.
- `run`, `prepare`, `teardown` run only inside the container, by `agentic-app`; arguments as arrays.
- Local commits only, no attribution lines; never push; never touch the user's containers or `~/work`.

## Review Focus

- An app name or value with shell or tmux specials (`#`, `;`, spaces) — refused (name) or passed literally (values).
- `prepare` failing or hanging — the start stops with its last lines, a timeout ends it, the state is `failed`.
- The agent editing the checkout's `agentic.yaml` — app commands come from the image's baked config, not the file.
- Two quick starts of the same app — one tmux window, the second is a no-op.
- A task with no `apps:` — `GET /apps` is `[]`, nothing else changes.

### Task 1: Config, validation and the label

**Files:** `schema/agentic.schema.json`, `image/lib/config-rules.jq`, `image/lib/config.sh` (validation),
`derive/render-dockerfile.sh` (`LABEL` line), `docs/configuration.md` (generated), tests `tests/bats/config.bats`,
`tests/bats/render.bats`, `tests/fixtures/render/*` as needed.

**Interfaces:** `apps:` per spec §3; label `agentic.apps` = base64 of `{name: {ports, url, autostart}}` (`e30=` for
none); the full apps config stays in the image's resolved config (where `agentic-app` reads it).

**Behaviours (tests first):** valid apps pass; a bad name, a port out of range, a duplicate port across apps, an
`env` key matching `TOKEN|KEY|SECRET|PASSWORD` (case-insensitive), an `env_files.from` with `..` or absolute path
are refused with a message naming the path; the label holds only ports, url, autostart; no apps → `e30=`;
`tools/gen-config-docs.sh --check` passes.

### Task 2: `agentic-app` in the image

**Files:** `image/bin/agentic-app` (new, 100755), `tests/bats/agentic-app.bats` (new, stub tmux and curl as in the
reference).

**Interfaces:** `agentic-app list [--json]` → `[{name, state, ports, url, since}]`; `start|stop|restart NAME`;
`logs NAME [--lines N]`; events via `POST $AGENTIC_BRIDGE_URL/app` with `Authorization: Bearer $AGENTIC_AGENT_TOKEN`
(header from a mode-600 temp file), body `{name, action, exit_code}`. Working dir: the task's checkout (`/work` or
`AGENTIC_WORK`) plus `dir`.

**Behaviours (tests first):** start opens window `app-<name>` on the tmux server `-L agentic-apps`; start of a running
app is a no-op; prepare runs once (marker), its failure → state failed, last 20 lines printed, event `failed`;
env_files copied before prepare; stop runs teardown; restart = stop + start; logs returns the window's last N
lines (N ≤ 2000) without control characters; an unknown name exits 1 "unknown app"; exit of the app posts
`exited` with its code; idle_stop stops an app whose ports saw no connection for the set time (test with a 2 s
value and a stub `ss`); no event post when the bridge is unset.

**Pitfalls:** tmux expands `#` in `-c` paths and commands — escape like the reference; commit the new script from
the index and check `git ls-tree HEAD image/bin/agentic-app` shows 100755.

### Task 3: Bridge routes and the `app` event

**Files:** `bridge/src/types.ts` (`EventType` + `"app"`), `bridge/src/api.ts` (routes), `bridge/src/task.ts` or the
module that records events, a small `bridge/src/apps.ts` (spawns `agentic-app` with an array, 60 s timeout for
start/restart, 10 s for the rest), tests `bridge/test/api.test.ts`, `bridge/test/apps.test.ts`.

**Interfaces:** spec §5 routes (task token); `POST /app` (agent token) → records `{type: "app", data: {name, action,
exit_code}}` (name checked, action one of started|stopped|exited|failed); autostart: after the checkout is ready,
start each `autostart` app of the label once.

**Behaviours (tests first):** `GET /apps` from `agentic-app list --json` (bad JSON → 502); actions 202 with the app,
404 unknown name (validated before spawning), 409 when the task is stopped; logs `lines` capped 2000, default 200;
`POST /app` with the agent token accepted, with a bad body 400; the agent token cannot call the control routes
(403); autostart runs once per task, not on every resume.

### Task 4: Smoke and docs

**Files:** `tests/image/smoke.sh` (a fixture app: `python3 -m http.server` on a port), the smoke fixture's
`agentic.yaml`, `docs/tasks.md` (Apps section), `docs/configuration.md` regenerated, `README.md` (one paragraph).

**Behaviours:** smoke starts a task with the fixture app, `GET /apps` shows it running, `curl` inside the container
reaches it, logs have the server's line, stop stops it. `make test`, `make lint`, `make smoke` pass.
