# Wiki skill and agent-context split — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `/wiki` skill and the `agentic-wiki` command in the base image. Together they write and check a project's agent knowledge: `docs/wiki/`, CLAUDE.md and path rules.

**Architecture:**
- `image/lib/wiki.sh` holds the page model: front matter as JSON, bodies, and generated blocks.
- `image/bin/agentic-wiki` holds four commands: `build`, `sync`, `check` and `affected`.
- Both are bash, yq and jq, and land in the image through the existing `COPY image/lib` and `COPY image/bin` lines.
- `skills/wiki/` is a base skill. `60-skills` copies it into both harnesses unchanged.

**Tech Stack:** bash, yq v4, jq 1.7, git, bats, shellcheck.

**Spec:** `docs/specs/2026-10-12-wiki-skill-design.md`

## Global Constraints

- **Locations:**
  - The wiki path is fixed at `docs/wiki/`. There is no config key.
  - The index import line in CLAUDE.md is exactly `@docs/wiki/index.md`.
- **Limits:**
  - The index is at most 70 lines and CLAUDE.md at most 130.
  - Component bodies are at most 80 lines, concept and flow bodies at most 60, the overview body at most 10. These counts are non-blank lines that are not headings, outside generated blocks.
  - On a component page: no table over 10 rows, and no more than 10 lines naming a path.
- **Generated content markers:**
  - A generated block sits between `<!-- generated:<name>:start -->` and `<!-- generated:<name>:end -->`.
  - Fully generated files start with `<!-- Generated by agentic-wiki build from the pages in docs/wiki/. Do not edit. -->`.
  - Rule mirrors carry `<!-- Generated by agentic-wiki sync from .claude/rules/<rel>. Do not edit. -->` on the line after their front matter.
- **Mirrors:** a rule mirror is `.github/instructions/<name>.instructions.md` with `applyTo: "<globs joined by ,>"`.
- **Bash style:** `set -euo pipefail`, short comments, shellcheck-clean, and a bats test for every behaviour, written first.
- **No `A && B || C`.** Write an `if` instead (SC2015).
- If shellcheck reports SC2016 on a jq or awk program in single quotes, add `# shellcheck disable=SC2016 # jq variables, not shell` on the line above, as `image/lib/config.sh` does.
- **Executable bits:** the repo is on `/mnt/c` with `core.fileMode=false`, so a new executable is added with `git add --chmod=+x`.
- **No company resources:** names, hosts, URLs or certificates. Examples use `example.com`. `make lint` runs the leak check.
- **Commits:** no `Co-Authored-By` or other attribution lines. No remote; do not push.
- **Verification:** every task ends with `make test` and `make lint` green. Task 7 also runs `make smoke`.
- **Never create a file named `CLAUDE.md` or a `.claude/` folder in this repository.**
  - Fixtures use `CLAUDE.fixture.md`, `dot-claude/` and `dot-github/`.
  - The template is `CLAUDE.template.md`.
  - This stops a harness that works on this repository from loading them.

## Review Focus

- **CRLF files from a Windows checkout:** a page saved with CRLF endings must parse the same as LF (Task 1, test "a page with CRLF line endings parses like LF").
- **Run from a subdirectory:** `agentic-wiki check` inside a git repository but below its root must find the root (Task 5, test "commands find the repository root from a subdirectory").
- **Running build and sync twice:** the second run changes nothing, otherwise `check` would always report stale files (Tasks 1 and 2, idempotence tests).
- **The user's own files:** text in `.github/copilot-instructions.md` outside the block, and hand-written `.github/instructions/*.instructions.md`, must survive `sync` (Task 2).
- **A brand-new wiki with only an overview:** must build and pass `check`, because that is where `seed` starts (Task 3, test "a wiki with only an overview builds and passes").

- [ ] **Step 5: Write `image/lib/wiki.sh`**

```bash
# Wiki helpers for agentic-wiki: pages, front matter and generated blocks. Source it; needs yq and
# jq. ROOT is the repository root; the pages live in $ROOT/docs/wiki.
WIKI_DIR=docs/wiki
# shellcheck disable=SC2034  # used by agentic-wiki
WIKI_GEN_NOTE='<!-- Generated by agentic-wiki build from the pages in docs/wiki/. Do not edit. -->'

# wiki_fm FILE: the front matter as one line of JSON. Returns 2 without front matter, 1 when it
# is not a YAML mapping. CRLF files parse like LF.
wiki_fm() {
  local yaml json
  [ "$(head -n 1 "$1" | tr -d '\r')" = --- ] || return 2
  yaml="$(tr -d '\r' < "$1" | awk 'NR == 1 { next } /^---[[:space:]]*$/ { exit } { print }')"
  json="$(printf '%s\n' "$yaml" | yq -o=json -I0 '.' 2>/dev/null)" || return 1
  [ "$(jq -r 'type' <<<"$json")" = object ] || return 1
  printf '%s\n' "$json"
}

# wiki_body FILE: the lines after the front matter.
wiki_body() {
  tr -d '\r' < "$1" | awk 'NR == 1 && /^---[[:space:]]*$/ { fm = 1; next }
    fm && /^---[[:space:]]*$/ { fm = 0; next }
    !fm { print }'
}

# wiki_authored FILE: the body without generated blocks.
wiki_authored() {
  wiki_body "$1" | awk '/^<!-- generated:[a-z-]+:start -->$/ { skip = 1 }
    !skip { print }
    /^<!-- generated:[a-z-]+:end -->$/ { skip = 0 }'
}

# wiki_pages: the authored pages relative to ROOT, sorted; generated files are left out.
wiki_pages() {
  [ -d "$ROOT/$WIKI_DIR" ] || return 0
  (cd "$ROOT" && find "$WIKI_DIR" -type f -name '*.md' | LC_ALL=C sort) \
    | grep -vxF -e "$WIKI_DIR/index.md" -e "$WIKI_DIR/decisions/index.md" -e "$WIKI_DIR/reuse.md" || true
}

# wiki_model: every page as {path, id, fm}; fm is null when the front matter is missing or invalid.
wiki_model() {
  local f id fm
  while IFS= read -r f; do
    id="${f#"$WIKI_DIR"/}"; id="${id%.md}"
    fm="$(wiki_fm "$ROOT/$f")" || fm=null
    jq -cn --arg path "$f" --arg id "$id" --argjson fm "$fm" '{path: $path, id: $id, fm: $fm}'
  done < <(wiki_pages) | jq -s '.'
}

# wiki_put_block FILE NAME: replaces the generated block NAME with stdin, appends it when it is
# missing, and removes it when stdin is empty. Everything outside the block is kept.
wiki_put_block() {
  local file="$1" start="<!-- generated:$2:start -->" end="<!-- generated:$2:end -->" content
  content="$(cat)"
  if [ -f "$file" ] && grep -qxF -- "$start" "$file"; then
    S="$start" E="$end" C="$content" awk '
      $0 == ENVIRON["S"] { skip = 1; if (ENVIRON["C"] != "") { print; print ENVIRON["C"]; print ENVIRON["E"] } next }
      $0 == ENVIRON["E"] { skip = 0; next }
      !skip { print }' "$file" > "$file.tmp"
    mv "$file.tmp" "$file"
  elif [ -n "$content" ]; then
    { if [ -s "$file" ]; then cat "$file"; echo; fi
      printf '%s\n%s\n%s\n' "$start" "$content" "$end"; } > "$file.tmp"
    mv "$file.tmp" "$file"
  fi
}

# rule_globs FILE: the rule's paths joined by commas; empty when it has none.
rule_globs() {
  { wiki_fm "$1" || echo '{}'; } | jq -r '.paths // empty | if type == "array" then join(",") else . end'
}
```

- [ ] **Step 6: Write `image/bin/agentic-wiki` with `build` and the dispatcher**

```bash
#!/usr/bin/env bash
# Builds, mirrors and checks the project wiki in docs/wiki/; the deterministic half of /wiki.
# Usage: agentic-wiki [-C DIR] build | sync | check | affected <git diff range>
set -euo pipefail
here="$(cd "$(dirname "$(readlink -f "${BASH_SOURCE[0]}")")" && pwd)"
AGENTIC_DIR="${AGENTIC_DIR:-$(cd "$here/.." && pwd)}"
# shellcheck source=../lib/wiki.sh
source "$AGENTIC_DIR/lib/wiki.sh"
usage() { echo "usage: agentic-wiki [-C DIR] build | sync | check | affected <git diff range>" >&2; exit 2; }

ROOT="$PWD"
if [ "${1:-}" = -C ]; then
  [ "$#" -ge 2 ] || usage
  ROOT="$(cd "$2" && pwd)"; shift 2
fi
need_wiki() { [ -d "$ROOT/$WIKI_DIR" ] || { echo "agentic-wiki: no $WIKI_DIR in $ROOT" >&2; exit 2; }; }

# --- build -------------------------------------------------------------------------------------

build_index() {
  local overview="" more="- [Decisions](decisions/index.md), [Reuse](reuse.md)"
  if [ -f "$ROOT/$WIKI_DIR/overview.md" ]; then
    overview="$(wiki_authored "$ROOT/$WIKI_DIR/overview.md" | { grep -v '^# ' || true; } | sed '/./,$!d')"
  fi
  printf '%s\n# Project wiki\n\n' "$WIKI_GEN_NOTE"
  printf '%s\n' "What the code does not tell: components, decisions, concepts and flows. Paths are relative to" \
    "docs/wiki/. Read a component's page before you change it. The code wins over the wiki; never" \
    "guess a page id."
  if [ -n "$overview" ]; then printf '\n%s\n' "$overview"; fi
  jq -r '
    def line: "- [\(.fm.name // .id)](\(.id).md): \(.fm.summary // "")";
    def section($t; $xs): if ($xs | length) > 0 then "\n## \($t)\n\n" + ($xs | map(line) | join("\n")) else empty end;
    section("Components"; map(select(.fm.kind == "component" and (.fm.parent // null) == null))),
    section("Concepts"; map(select(.fm.kind == "concept"))),
    section("Flows"; map(select(.fm.kind == "flow")))' <<<"$1"
  if [ -f "$ROOT/$WIKI_DIR/glossary.md" ]; then more+=", [Glossary](glossary.md)"; fi
  printf '\n## More\n\n%s\n' "$more"
}

build_decisions() {
  printf '%s\n# Decisions\n\n' "$WIKI_GEN_NOTE"
  jq -r '[.[] | select(.fm.kind == "decision")]
    | sort_by((.id | capture("adr-(?<n>[0-9]+)$") // {n: "0"}).n | tonumber)
    | if length == 0 then "No decisions recorded yet."
      else map("- [\(.fm.title // .id)](\(.id | ltrimstr("decisions/")).md): \(.fm.status // "")") | join("\n") end' <<<"$1"
}

build_reuse() {
  printf '%s\n# Reuse\n\nFunctions the components offer for reuse. Check here before you write a helper.\n\n' "$WIKI_GEN_NOTE"
  jq -r '[.[] | select(.fm.kind == "component") as $c
      | ($c.fm.offers | if type == "array" then .[] else empty end) | select(type == "object")
      | {name: (.name // ""), location: (.location // ""), use: (.use // ""), cid: $c.id, cname: ($c.fm.name // $c.id)}]
    | sort_by(.name)
    | if length == 0 then "No reusable functions recorded yet."
      else (["| Function | Location | Use | Component |", "|---|---|---|---|"]
        + map("| \(.name) | `\(.location)` | \(.use) | [\(.cname)](\(.cid).md) |")) | join("\n") end' <<<"$1"
}

# build_used_by MODEL: the reverse of depends_on, written into each component page.
build_used_by() {
  local id path dir u name content
  while IFS=$'\t' read -r id path; do
    dir="$(dirname "$ROOT/$path")"
    content=""
    while IFS=$'\t' read -r u name; do
      content+="- [$name]($(realpath -m --relative-to="$dir" "$ROOT/$WIKI_DIR/$u.md"))"$'\n'
    done < <(jq -r --arg id "$id" '.[] | select(.fm.depends_on | if type == "array" then any(.[]; . == $id) else false end)
      | [.id, (.fm.name // .id)] | @tsv' <<<"$1")

    wiki_put_block "$ROOT/$path" used-by <<<"$content"
  done < <(jq -r '.[] | select(.fm.kind == "component") | [.id, .path] | @tsv' <<<"$1")
}

cmd_build() {
  local model
  model="$(wiki_model)"
  mkdir -p "$ROOT/$WIKI_DIR/decisions"
  build_index "$model" > "$ROOT/$WIKI_DIR/index.md"
  build_decisions "$model" > "$ROOT/$WIKI_DIR/decisions/index.md"

  build_used_by "$model"
  echo "built $WIKI_DIR/index.md, decisions/index.md, reuse.md and the Used by blocks"
}
```

```bash
# cmd_sync: mirrors .claude/rules to .github/instructions (only files it generated are ever
# removed) and puts the index into .github/copilot-instructions.md, keeping the text around it.
cmd_sync() {
  local src rel name out globs
  declare -A keep=()
  if [ -d "$ROOT/.claude/rules" ]; then
    while IFS= read -r src; do
      globs="$(rule_globs "$src")"
      if [ -z "$globs" ]; then continue; fi
      rel="${src#"$ROOT/.claude/rules/"}"; name="${rel%.md}"; name="${name//\//-}"
      out="$ROOT/.github/instructions/$name.instructions.md"

        printf '<!-- Generated by agentic-wiki sync from .claude/rules/%s. Do not edit. -->\n' "$rel"

  if [ -d "$ROOT/.github/instructions" ]; then
```

```bash
# check_pages MODEL: front matter shape, kinds, required fields, allowed values, references.
check_pages() {
  jq -r '
    def kind_for: if startswith("components/") then "component"
      elif test("^decisions/adr-[0-9]+$") then "decision"

      echo "$path: source $src is also claimed by ${claimed[$e]}"
    else
      claimed[$e]="$path"
    fi
  done < <(jq -r '.[] | select(.fm.kind == "component") | .path as $p
      | (.fm.sources | if type == "array" then .[] else empty end) | select(type == "string") | [$p, .] | @tsv' <<<"$1")

# check_links MODEL: relative links in authored text resolve to a file in the repository.
check_links() {

      *) continue ;;

  if [ -d "$ROOT/.github/instructions" ]; then

      if [ ! -e "$tmp/$f" ]; then stale_note "$f"; fi

  fi

}

cmd_check() {
  local model n=0 line
  if [ ! -d "$ROOT/$WIKI_DIR" ]; then echo "agentic-wiki: no $WIKI_DIR; nothing to check"; return 0; fi

  echo "wiki: ok"
}
```

```bash
# --- affected ----------------------------------------------------------------------------------

# cmd_affected RANGE: maps the files git diff lists to the component with the longest matching
# source; omitted.yaml paths print as omitted, the rest as unclaimed.
cmd_affected() {
  local files f e best id src
  declare -A owner=()
  files="$(git -C "$ROOT" diff --name-only "$1")" || exit 2
  while IFS=$'\t' read -r id src; do
    owner["${src%/}"]="$id"
  done < <(wiki_model | jq -r '.[] | select(.fm.kind == "component") | .id as $i
      | (.fm.sources | if type == "array" then .[] else empty end) | select(type == "string") | [$i, .] | @tsv')
  if [ -f "$ROOT/$WIKI_DIR/omitted.yaml" ]; then
    while IFS= read -r e; do
      if [ -n "$e" ]; then owner["${e%/}"]="-"; fi
    done < <(yq -r '.paths[]?.path // ""' "$ROOT/$WIKI_DIR/omitted.yaml")
  fi
  while IFS= read -r f; do
    case "$f" in
      ""|"$WIKI_DIR"/*|.claude/*|.github/instructions/*|.github/copilot-instructions.md|CLAUDE.md) continue ;;
    esac
    best=""
    for e in "${!owner[@]}"; do
      if [ "$f" = "$e" ] || [[ "$f" == "$e"/* ]]; then
        if [ "${#e}" -gt "${#best}" ]; then best="$e"; fi
      fi
    done
    if [ -z "$best" ]; then
      echo "unclaimed $f"
    elif [ "${owner[$best]}" = - ]; then
      echo "omitted $f"
    else
      echo "component ${owner[$best]} $f"
    fi
  done <<<"$files"
}
```

```markdown
# Wiki

Agents read code well. What they cannot read from it is what each component is for and where its
limits are, where a change belongs, which contracts others rely on, what must stay true, why it is
built this way, which shared code already exists, and how the business flows run. That knowledge
lives in three places, and this skill writes all three:

- **CLAUDE.md**, always loaded: what the project is, how to work, commands, rules for every task.
  It imports the wiki index with `@docs/wiki/index.md`. Copilot CLI reads the same file.
- **Path rules** in `.claude/rules/<area>.md` with `paths:`, loaded when those paths are touched.
- **The wiki** in `docs/wiki/`: component pages, decisions, concepts, flows, a glossary.

Read `reference/routing.md` before you move or write anything, and `reference/pages.md` before you
write a page. Start every page from `templates/`.

## The routing test

For every statement, in order; the first match decides:

1. The code says it, or a command prints it → nowhere; at most a pointer to the folder or command.
2. A repeated procedure → a skill or a template, plus one line in CLAUDE.md naming it.
3. An instruction for every task, where removing it would cause mistakes → CLAUDE.md.
4. An instruction for some paths only → a path rule.
5. A description the code does not reveal → a wiki page.

Instructions go to CLAUDE.md or rules, descriptions to the wiki. When both are needed, the rule
says what to do in one line and links the page that says why.

The test for a wiki sentence: would a senior engineer tell a new colleague this before they touch
the component, because an hour of reading the code would not reveal it? Under-claim rather than
over-claim. The code wins over the wiki.

## Commands

`agentic-wiki` does everything a script can decide. Run it from anywhere in the repository.

- `agentic-wiki build`: writes `index.md`, `decisions/index.md`, `reuse.md` and the "Used by"
  blocks from the pages.
- `agentic-wiki sync`: mirrors `.claude/rules/` to `.github/instructions/` for Copilot and puts the
  index into `.github/copilot-instructions.md`.
- `agentic-wiki check`: validates pages, sources, links, sizes, CLAUDE.md, rules and generated
  files. Fix every line it prints.
- `agentic-wiki affected <range>`: maps changed files to components. `<base>..<head>` compares
  commits; `<base>` alone also covers uncommitted changes. Untracked files need `git status`.

After any change: `build`, `sync`, `check`, until `check` prints `wiki: ok`.

## Modes

### seed

Once per repository.

1. Read the layout of the code, the existing CLAUDE.md, AGENTS.md, `.claude/rules/`,
   `.github/copilot-instructions.md`, `.github/instructions/` and `docs/`.
2. Define the components: logical blocks with one responsibility each, whose `sources` may span
   code, infrastructure, configuration, migrations and pipelines. Aim for 5 to 25 top-level
   components; give a part its own page only when it has its own folder or file boundary. Put
   paths that belong to no component into `omitted.yaml` with a reason.
3. Write `overview.md`, then one page per component, then the decisions, concepts, flows and the
   glossary the code and the documents support. Seeded pages are `status: draft`.
4. Route every statement of the existing instruction files with the test. Rewrite CLAUDE.md from
   `templates/CLAUDE.template.md`, keeping every instruction that passes. Turn area instructions
   into rules from `templates/rule.md`. A hand-written `.github/instructions/` file whose content
   you moved into a rule is replaced by its mirror.
5. Run `build`, `sync`, `check` until it passes.
6. Summarise: pages written, statements moved (from → to), statements dropped because the code
   says them (with the reason), and "Needs a human".

### update [<range>]

At the end of a task before the PR, or as a catch-up. Without a range use
`$(git merge-base HEAD <default branch>)`, which also covers uncommitted changes.

1. Run `agentic-wiki affected <range>`.
2. For each component listed, read `git diff <range> -- <its files>` and its page. Correct only
   the claims the diff contradicts. Check `depends_on`, `offers` and `lifecycle` against the code.
   Add what the change decided: a boundary, a why, a new offer, a pitfall it hit.
3. Each unclaimed file: add it to the `sources` of the component that owns it, write a new
   component, or add it to `omitted.yaml`. A removed component loses its page and every link to it.
4. Route any new instruction the change brought to CLAUDE.md or a rule.
5. Run `build`, `sync`, `check`. Summarise the changes, or print `wiki: no changes`.

### add "<fact>"

Route the fact with the test, write it where it belongs, then `build`, `sync`, `check`, and say
where it went.

### audit

Change nothing. Run `agentic-wiki check`, then report what a script cannot see: statements in the
wrong layer, the same statement in two layers, claims the code contradicts, pages that copy the
code, components without a page, and CLAUDE.md lines that fail "would removing this cause
mistakes?".

## Guardrails

- Moving is fine; losing is not. A statement you take out of CLAUDE.md or a rule is moved to its
  new place or listed in the summary as dropped, with the reason.
- Never edit a generated file or block; change the pages and run `build` and `sync`.
- Never write or change the decision of an ADR on your own. Put a proposed draft under "Needs a
  human".
- No ticket ids in pages, except in ADRs that already cite them.
- Write only CLAUDE.md, `.claude/rules/`, `.github/instructions/`,
  `.github/copilot-instructions.md` and `docs/wiki/`. Do not commit.
- Plain, results-only prose in full sentences; no process narrative.
```

```markdown
## Layout

`[ADR-3](../decisions/adr-3.md)`; links to code files are fine. `agentic-wiki check` resolves them.

## Component

Front matter: `id`, `kind: component`, `name`, `summary` (one line; it is the component's line in
the index), `parent` (for sub-components), `lifecycle` (`active`, `migrating`, `retiring`),
`status` (`draft`, `reviewed`), `sources`, `depends_on`, `decisions`, `offers`.

- `sources`: folders or files of any kind (code, Terraform, configuration, migrations,
  pipelines), relative to the repository root. No two components claim the same entry; the
  longest matching entry owns a file.
- `depends_on`: components and concepts it needs at run time, in one direction; `build` writes the
  reverse as "Used by".
- `offers`: reusable functions, each `name`, `location` (`path` or `path::symbol`) and `use` (one
  line). `build` collects them into `reuse.md`.

Body sections, in this order, each left out when empty:

- **Purpose and boundary**: what the component owns and what it must not do.
- **Where changes go**: the place for the two or three most common changes.
- **Contracts**: what it exposes or consumes that others rely on, whether it is fixed, where the
  schema lives. No field lists.
- **Invariants**: what must stay true, tested or not.
- **Why**: links to ADRs, local decisions, rejected alternatives.
- **Pitfalls**: known traps.
- **Outside the repo**: external systems, consumers, other repositories.

Limits: at most 80 non-blank lines outside headings and generated blocks; no table longer than 10
rows; no more than 10 lines naming paths. Lists of routes, fields, tables or parameters belong to
the code.

|---|---|---|
| `decision` | `id`, `kind`, `title`, `status` (`proposed`, `accepted`, `superseded`), optional `superseded_by` | Context, Decision, Consequences |
| `concept` | `id`, `kind`, `name`, `summary`, optional `related` | A few paragraphs; at most 60 lines |
| `flow` | `id`, `kind`, `name`, `summary`, `components` | Trigger, steps naming components, outcome, failure paths; at most 60 lines |
| `overview` | `id: overview`, `kind: overview` | At most 10 lines |
| `glossary` | `id: glossary`, `kind: glossary` | One line per term: term, meaning, link |

component page sits between `<!-- generated:used-by:start -->` and
```
