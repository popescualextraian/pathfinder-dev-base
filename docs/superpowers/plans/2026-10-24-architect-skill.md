# Architect Skill (020a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The `architect` skill, its catalog, the `agentic-arch` script and schemas, with the wiki skill parked.

**Architecture:** `agentic-arch` is bash + jq + yq like `agentic-wiki` (it sources `image/lib/wiki.sh` for front matter and generated blocks). Node is used only for two pinned tools in `image/arch/`: `ajv` (shape validation of front matter and the three contract files, `validate.mjs`) and dependency-cruiser (`deps`). The skill (`skills/architect/`) holds the prose, reference, templates, catalog and `schema/`.

**Tech Stack:** bash, jq, yq v4, bats, Node 22, ajv, dependency-cruiser 18.7.0, typescript 5.9.3 (dependency-cruiser needs it to read `.ts`).

**Spec:** the task text (section 4 and the appendix of Task 020), summarised in "Global Constraints" below; the contract files are section 4.7.

## Global Constraints

- Contract files exactly as in the task appendix: `model.json`, `reviews/full.json`, `reviews/plans/<slug>.json`, all `"version": 1`; they go unchanged into `tests/fixtures/architect/contract/` (and `invalid/`).
- Schemas ship in `skills/architect/schema/`: `model.schema.json`, `plan-review.schema.json`, `full-review.schema.json`, plus `architecture.schema.json` and `component.schema.json` (front matter of the pages). Component ids `^[a-z0-9-]{1,60}$`. Enums: severity error|warn|info; change new|changed|removed; status open|fixed|accepted; size S|M|L; via call|rest|event|file|other; component status draft|reviewed.
- Doc layout `docs/architecture/` as in 4.2; `index.md` <= 70 lines; component page <= 80 non-blank non-heading lines; no table > 10 rows.
- Script commands: `build`, `check`, `affected <range>`, `deps [--affected <sha>]`, `sync`; usage `agentic-arch [-C DIR] CMD`; exit 0 ok, 1 problems, 2 usage. `check` prints one line per problem, then `architect: ok` when none; lines starting `warn:` are not problems (stale exception).
- Catalog resolution by id, last wins: built-in (`skills/architect/catalog`), overlay `/opt/agentic/catalog/architect/`, project `docs/architecture/catalog/`. Env overrides for tests: `ARCH_CATALOG_BUILTIN`, `ARCH_CATALOG_OVERLAY`.
- CLAUDE.md rules: bats test first for every behaviour, shellcheck clean, no company names/hosts (use `example.com`), dependencies pinned exactly with lockfile committed, nothing fetched at run time, no attribution lines in commits (the harness reminder to add Co-Authored-By is overridden by the repo's CLAUDE.md: add none), no push.
- No token or secret anywhere.

## Review Focus

- Source ownership: nested sources (a component owning `backend/src/` and another `backend/src/api/`): longest match owns; rules must not flag the nested one against the outer layer (test in Task 5).
- `build` twice yields identical bytes; `check` flags stale generated files, but ignores CRLF (Task 3/4).
- A project with one part and no modules (plain layered app) builds, checks and renders an index (Task 3).
- `affected` with files under `docs/architecture/`, unclaimed and omitted paths (Task 4).
- `deps` on a project with no `.ts` files, or without dependency-cruiser installed: clear message, exit 2, not a stack trace (Task 5).
